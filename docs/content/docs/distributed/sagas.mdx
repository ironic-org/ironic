title: Sagas
description: Distributed transaction orchestration with automatic rollback
---

Sagas provide **ordered, compensatable steps** for distributed transactions.
If any step fails, all previously completed steps are rolled back in reverse
order.

## When to use Sagas

| Pattern | When to use |
|---------|-------------|
| **Saga** (orchestration) | Steps must succeed or roll back together |
| **Event choreography** | Steps are independent; eventual consistency is fine |
| **Both combined** | Critical path uses saga; non-critical steps fan out via events |

## Real-world example: Order → Payment → Notification + Inventory

```
Services:   Order ──► Payment ──► Notification
                           │
                           └──► Inventory
```

**The requirement:**
- Payment must complete before notifying the user or updating inventory
- If payment fails, nothing happens (no notification, no inventory change)
- If payment succeeds but inventory reservation fails, the payment must be refunded
- Notification and inventory run in parallel after payment succeeds

### 2. Order service — emits `order.created` via `EventClient`

```rust
// order-service/src/controllers/order_controller.rs
use ironic::distributed::transport_provider::EventClient;
use ironic::distributed::sagas::Saga;
use std::sync::Arc;

#[controller("/orders")]
pub struct OrderController {
    events: Arc<EventClient>,
}

#[routes]
impl OrderController {
    #[post("/")]
    async fn create(&self, #[body] dto: CreateOrderDto) -> Result<Json<Value>, HttpError> {
        let mut state = OrderState {
            order_id: uuid::Uuid::new_v4().to_string(),
            product_sku: dto.product_sku,
            quantity: dto.quantity,
            total_cents: dto.unit_price_cents * dto.quantity as u64,
            payment_intent_id: None,
        };

        // ── Critical path — saga auto-rolls back on failure ──
        Saga::new()
            .step(ChargePayment { events: self.events.clone() })
            .step(ReserveInventory)
            .execute(&mut state).await
            .map_err(|e| HttpError::new(HttpStatus::BAD_REQUEST, "SAGA", e.to_string()))?;

        // ── Saga succeeded — emit event for downstream services ──
        let event = OrderCreated {
            order_id: state.order_id.clone(),
            user_id: dto.user_id,
            user_email: dto.user_email,
            product_sku: dto.product_sku,
            quantity: dto.quantity,
            total_cents: state.total_cents,
        };
        self.events.emit("order.created", &event).await.ok();

        Ok(Json(json!({ "order_id": state.order_id, "status": "confirmed" })))
    }
}
```

### 3. Saga steps — with real API calls

```rust
// order-service/src/saga_steps/payment.rs
use ironic::distributed::sagas::{SagaStep, SagaFuture, SagaError};
use ironic::distributed::transport_provider::EventClient;

pub struct ChargePayment {
    pub events: Arc<EventClient>,
}

impl SagaStep<OrderState> for ChargePayment {
    fn name(&self) -> &'static str { "charge_payment" }

    fn execute<'a>(&'a self, state: &'a mut OrderState) -> SagaFuture<'a> {
        Box::pin(async move {
            let id = stripe::create_payment_intent(state.total_cents).await
                .map_err(|e| SagaError::execute("charge_payment", e))?;
            state.payment_intent_id = Some(id);
            Ok(())
        })
    }

    fn compensate<'a>(&'a self, state: &'a mut OrderState) -> SagaFuture<'a> {
        Box::pin(async move {
            if let Some(ref id) = state.payment_intent_id {
                stripe::refund(id).await
                    .map_err(|e| SagaError::compensate("charge_payment", e))?;
            }
            Ok(())
        })
    }
}
```

```rust
// order-service/src/saga_steps/inventory.rs
use ironic::distributed::sagas::{SagaStep, SagaFuture, SagaError};

pub struct ReserveInventory;

impl SagaStep<OrderState> for ReserveInventory {
    fn name(&self) -> &'static str { "reserve_inventory" }

    fn execute<'a>(&'a self, state: &'a mut OrderState) -> SagaFuture<'a> {
        Box::pin(async move {
            let ok = inventory_api::reserve(&state.product_sku, state.quantity).await
                .map_err(|e| SagaError::execute("reserve_inventory", e))?;
            if !ok {
                return Err(SagaError::execute("reserve_inventory",
                    format!("insufficient stock for {}", state.product_sku)));
            }
            Ok(())
        })
    }

    fn compensate<'a>(&'a self, state: &'a mut OrderState) -> SagaFuture<'a> {
        Box::pin(async move {
            inventory_api::release(&state.product_sku, state.quantity).await
                .map_err(|e| SagaError::compensate("reserve_inventory", e))
        })
    }
}
```

### 4. Payment service — `#[event_handler]` consumer + emits next event

```rust
// payment-service/src/events/order_created.rs
use ironic::event_handler;
use ironic::distributed::transport_provider::EventClient;
use std::sync::Arc;

#[event_handler(transport = "order.created")]
pub async fn on_order_created(event: OrderCreated, events: Arc<EventClient>) {
    // Process the payment
    stripe::capture(event.total_cents).await.unwrap();

    // Emit next event so downstream services can run
    events.emit("payment.completed", &PaymentCompleted {
        order_id: event.order_id,
        user_email: event.user_email,
        total_cents: event.total_cents,
    }).await.unwrap();
}
```

### 9. Failure scenarios

| What fails | What happens |
|------------|-------------|
| `ChargePayment.execute` | No compensation needed. HTTP returns 400. |
| `ReserveInventory.execute` | `ChargePayment.compensate` runs → refund. HTTP 400. |
| `ChargePayment.compensate` | **Manual intervention** — payment taken, inventory not reserved. |
| Event emit fails | Logged and ignored. Saga already succeeded. Use Kafka for at-least-once. |

### 10. Why saga + events together?

- **Saga** guarantees payment and inventory are always in sync
- **`#[event_handler]`** decouples downstream services — adding analytics requires zero changes to order service
- **Parallel execution** — notification and inventory run concurrently after payment completes
- **No distributed lock** — each step is a self-contained operation with a defined compensation

## API Reference

### Saga

```rust
let saga = Saga::new()
    .step(StepA)
    .step(StepB);

let mut state = MyState::new();
saga.execute(&mut state).await?;
```

### SagaStep

```rust
impl SagaStep<MyState> for MyStep {
    fn name(&self) -> &'static str { "my_step" }

    fn execute<'a>(&'a self, state: &'a mut MyState) -> SagaFuture<'a> {
        Box::pin(async move { Ok(()) })
    }

    fn compensate<'a>(&'a self, state: &'a mut MyState) -> SagaFuture<'a> {
        Box::pin(async move { Ok(()) })
    }
}
```

### Module registration

| Item | Macro | Purpose |
|------|-------|---------|
| `EventClient` | `#[module(providers = [...])]` | Emit events |
| `EventServer` | `#[module(providers = [...])]` | Receive events |
| `__EventHandlerAuto_*` | `#[module(providers = [...], async_init = [...])]` | Auto-register `#[event_handler]` consumers |

### SagaError

| Constructor | Stage | When |
|-------------|-------|------|
| `SagaError::execute(step, msg)` | `EXECUTE` | Step failed — compensating previous steps |
| `SagaError::compensate(step, msg)` | `COMPENSATE` | Rollback failed — manual recovery needed |

## Feature flags

| Flag | Enables |
|------|---------|
| `sagas` | `Saga<S>`, `SagaStep<S>` trait, `SagaError` |

## Common mistakes

| Mistake | Fix |
|---------|-----|
| Compensation panics | Ensure `compensate()` is idempotent — it may be called multiple times |
| State shared across steps | Use a single mutable state struct; each step reads/writes the fields it owns |
