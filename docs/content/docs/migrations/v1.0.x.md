# Migration Guide — v1.0.x

This guide covers breaking changes introduced in the v1.0.x release line, which
applies on top of the [v0.3.x guide](/docs/migrations/v0.3.x).

---

## 1. `FrameworkRequest` / `FrameworkResponse` renamed to `Request` / `Response`

**What changed (v1.0.4):**

The long-form type names were shortened:

| Old (v0.3.x) | New (v1.0.x) |
|--------------|-------------|
| `FrameworkRequest` | `Request` |
| `FrameworkResponse` | `Response` |
| `FrameworkBody` | `Body` |
| `FrameworkApplication` | `Application` |

**Old code (v0.3.x):**

```rust
use ironic::http::FrameworkRequest;

async fn handler(req: FrameworkRequest) -> FrameworkResponse {
    FrameworkResponse::ok_json(json!({"ok": true}))
}
```

**New code (v1.0.x):**

```rust
use ironic::{Request, Response};

async fn handler(req: Request) -> Response {
    Response::ok_json(json!({"ok": true}))
}
```

### Migration steps

1. Replace `FrameworkRequest` → `Request` and `FrameworkResponse` → `Response` in imports and type annotations
2. Replace `FrameworkBody` → `Body` in serialization and streaming code
3. Replace `FrameworkApplication` → `Application` where you reference the app type
4. Let `cargo build` guide the rest — the compiler flags every remaining usage

> The `Request` / `Response` types are exported from the crate root — no need for
> the `http::` module path in most cases.

## 2. Removed deprecated lifecycle hooks

**What changed (v1.0.9):**

The `OnRequestInit` and `OnServerReady` hooks were removed, along with the
related lifecycle overview docs.

**Old code (v0.3.x):**

```rust
impl OnRequestInit for TraceInitializer {
    fn on_request(&self, req: &mut FrameworkRequest) { /* ... */ }
}
```

**New code (v1.0.x):**

Use `AsyncModuleInit` (or module `on_init`) for startup work, and interceptors
for per-request work:

```rust
use ironic::prelude::*;

impl AsyncModuleInit for TraceModule {
    async fn async_init(&self, container: &Container) -> Result<(), LifecycleError> {
        // startup setup
        Ok(())
    }
}
```

### Migration steps

1. Move `OnServerReady` startup logic into `AsyncModuleInit::init()`
2. Move `OnRequestInit` per-request logic into an interceptor or middleware
3. Update your module imports — the hook traits no longer exist

---

## 3. Removed `NotFoundFilter`

**What changed (v1.0.4):**

The `NotFoundFilter` exception filter was removed in favor of the default 404
handling.

### Migration steps

1. Delete any `catch(NotFoundFilter::new())` registrations
2. If you customized 404 responses, implement a `catch(Arc<dyn ExceptionFilter>)`
   matching `HttpStatus::NOT_FOUND` instead
